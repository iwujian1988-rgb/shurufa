## 交互与质量原则

- 中文候选为主要输入目标，目标语言释义可读但视觉上次于中文。
- 常规点选提交中文；若增加译词上屏，必须提供明确且不易误触的操作。
- 从首轮设计就验证英文、法文、重音字符、长词和多词短语。候选刷新不得改变正在触摸的目标，不让栏高随译词跳动。
- 按键即时反馈，动画不延迟输入，震动可关闭；浅深色、大字体、横屏、无障碍和键盘切换纳入验收。
- 核心输入和释义保持离线可用，翻译或模型异步结果不得阻塞基本打字。
- 密码与敏感输入不进入新增日志、学习或网络请求。各平台按其输入接口落实并验证。
- 不以编译成功替代真机验收，不以漂亮截图替代连续输入体验，不声称词级释义具有完整语境翻译能力。

性能初始讨论目标是在指定中端真机 release 包上，95% 的正常热态按键到候选显示延迟低于 50ms。该数字是拟定目标，未实测；需规定设备、词库、模型、输入场景与统计口径，再根据基线确认。冷启动、内存、耗电和准确性也需建立基线。

## 本轮实现边界

新代码在 `mobile/native/`、`mobile/android/`；英语与法语学习数据在 `data/`；构建与验收脚本在 `scripts/`。中文词库、英语表、二元模型、解析排序和学习复用固定上游。JNI 引擎按线程内句柄管理，单线程执行器顺序调用；会话代次屏蔽旧输入框回调，候选 revision 防止错提交。

当前支持全键与九宫格拼音、译词候选、展开、中文上屏、字母模式、数字符号、法语重音字符、空格、回车、连续删除、系统输入法切换、主题与震动设置、启用指引、无须启用系统键盘的内置试打。九宫格当前每段最多 32 键、最多 8 条词路径。没有声称完整法语补全、云模型、语音、滑行或复习系统。

下一轮先收集用户手机实际体验，再处理候选质量、跨应用/敏感输入/光标行为、大小字体与横屏、启动资源和速度基线；同时扩充英语/法语高频数据并独立校审。PC 保持 Windows 双产品隔离方案，iOS 仍以前置许可与扩展原型验证为下一平台条件。

后续每条记录应写清发生了什么、涉及哪些文件或构建、用什么验证，失败时保留具体影响和下一步。
