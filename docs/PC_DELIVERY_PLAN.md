# 词伴 PC 版交付方案

实施更新 2026-10-04：已按此方案生成 0.1.0-demo.1 英法双安装器，Windows 11 x64 + x86 TSF。实际路径采用 upstream/crates/ciban-lexicon 和 products/windows.json，避免新增另一份工作区。Rust stable 1.95.0 已完成实际 release 编译。双产品核心/实际 pipe 回归已通过，安装注册、设置实屏、跨应用、升级卸载及正式签名未完成；本文件下方初始源码发现属于实施前记录，不能继续按“未编译”恢复。当前操作入口 ../desktop/windows/BUILD.md，证据 ../deliverables/Windows验收记录.md。

日期：2026-10-04（Asia/Shanghai）。状态：已完成锁定源码检查与 Windows Cargo 工作区元数据检查，尚未编译、安装或验收词伴 Windows 成品。用户本轮要求继续规划 PC 开发，关注最少重复工作、开发效率、交互与交付质量。

## 建议结论

首期 Windows 11 x64：直接复用上游 Windows TSF、Server、候选渲染、设置及 Inno 安装流程；复用本项目中文词库、英法词义源和生成器。抽出安卓已有的读音词义模块供两端使用，不把 Kotlin 键盘或 JNI 会话层搬到 PC。

保留英语、法语两个独立安装包，一套源码构建。先做双产品标识和数据布局，再打通英语实际输入闭环；法语使用同一流程接入，并同轮验收并存。后续验证 Windows 10；macOS、Windows ARM64 和 iOS 不放进第一次 Windows 验收范围。

“Windows x64”不等于只生成一个 64 位 DLL：上游已经支持 x64 Server + x64/x86 TSF DLL，必须保留，否则 64 位系统上的 32 位应用不能正常加载我们的输入法。这不代表支持 32 位 Windows 系统。

## 基于当前代码的复用与缺口

| 部分 | 已有实现 | 本项目需要做的工作 |
| --- | --- | --- |
| 中文输入引擎 | upstream/crates/qingjian-core、dictionary、lm、learning | 继续复用，避免重写拼音、排序、整句与基础学习 |
| Windows 系统接入 | upstream/apps/windows/tsf | 产品独立注册、服务发现、断连恢复与实际应用验收 |
| 独立引擎进程 | upstream/apps/windows/server | 装配目标语言、共享词义标注、固定数据版本与产品配置 |
| 候选展示 | qingjian-render 与 Windows ui | 中文/译词层级、长法语、DPI/多屏定位、无焦点干扰的详情入口 |
| 设置与安装 | Windows settings（WinUI 3）、installer（Inno） | 改为词伴品牌，精简设置；独立安装、升级、卸载、签名与源码对应 |
| 英法词义与学习详情 | mobile/native/src/english.rs、french.rs，session.rs::annotate_learning | 提取平台无关查询和标注，接入桌面候选及详情；不是仅改 language="fr" |
| 数据来源与生成 | data/、build-french-data.cjs、build-english-data.cjs、pack-assets.rs | 保留各自许可；建立平台无关打包入口，避免 Windows 依赖 Android assets 目录 |
| 发布与自动更新 | 上游 qingjian-update、官网 APK 下载 | Windows 首轮手动升级，关闭上游更新检查；以后独立签名索引与 PC 分发规则 |

具体发现：

- Windows 三个 package 当前都是 0.1.5-dev，锁定源码见 upstream-lock.json；不能因为上游曾发布 Windows 版，就说词伴 PC 已经可用。
- DEFAULT_PIPE_NAME 固定为 `\\.\pipe\qingjian`，用户目录固定 `%APPDATA%\Qingjian`，启动/安装互斥量以及安装器 AppId、名称与路径也固定；只改界面名称会产生冲突。
- 移动端词义使用“中文词头＋候选读音”，在查询后覆盖候选短释义并生成详情。桌面现有装配加载普通 Glossary，尚未接入移动端这套多读音保护与整理记录。
- 上游配置模板 `input_log = true`、更新检查默认开启。词伴默认关闭逐次输入日志、详细内容日志及上游更新检查；云预测默认关闭且首轮设置页不开放未验收的入口。
- 设置程序沿用 WinUI 3，自包含运行时在上游说明中约 56 MB。先验证复用，不能仅为省安装体积再写一套设置框架。
- 上游 rust-toolchain.toml 固定 1.96.0，本机仅有 stable 1.95.0。1.95.0 下离线 Cargo 元数据能解析三个 Windows package，不代表 Windows 编译已通过。第一阶段统一工具链再验证；不为绕过失败随意降级依赖。

## 最小工程调整

建议在现有项目中新增以下目录，保持一个源码仓库和一份进度真源：

```text
shared/ciban-lexicon/       英法读音查询、候选短释义与学习详情；不依赖 JNI 或 Windows API
products/english.toml      英语固定产品配置
products/french.toml       法语固定产品配置
desktop/windows/           本项目构建入口、资源、产品打包及验收
upstream/apps/windows/     在现有平台实现上做必要修改，记录补丁
```

这些目录是待实施设计，当前尚未创建对应 Rust/Windows 实现。不再复制一份完整 upstream，更不复制英语工程当法语工程。

共享词义模块保留现有精确读音、未整理读音保护、词典来源、审核标记与缺字段行为。PC 和 Android 对同一候选的词义结果应一致；Windows 单独承担按键、TSF 提交和窗口生命周期，移动会话、九宫格和 JNI 留在移动端。

候选短释义必须走共用模块，学习详情按需查询，不能让查详情或网络阻塞上屏。新协议字段保持可选兼容；新消息需明确版本，Server 与 DLL 配套打包，并测试旧 DLL 仍在已打开应用中的升级状态。不能只让协议不匹配时记日志后继续冒险处理。

## 双包隔离先做好

产品配置生成跨 Server、TSF、设置与安装器一致的常量，并验证英语/法语 ID 不重复。TSF 产品身份在构建时确定，不能依赖运行时随意修改语言配置来变成另一产品。

| 内容 | 隔离规则 |
| --- | --- |
| Windows COM CLSID、语言 profile GUID | 两产品独立；实际输入语言仍为中文，伴学语言分别为英语/法语 |
| 安装器 AppId、路径、卸载键、快捷方式、图标 | 独立，升级一个产品不覆盖另一个或上游青简 |
| Server / settings 可执行文件与 TSF DLL | 独立名称，防止按进程名停服务时误杀另一产品 |
| IPC 管道、启动互斥量、安装互斥量 | 区分产品，并验证用户/登录会话隔离与访问权限 |
| 用户配置、学习记录、统计、日志 | 建议 `%APPDATA%\Ciban\English` / `French` 等独立目录；升级保留，卸载清理需明确选择 |
| 随包资源 | 只带本产品需要的目标语言，中文基础资源可来自同一打包真源；使用不可变版本目录与内容清单 |
| 更新索引、版本、签名、下载记录 | 不连接上游更新服务器，不复用安卓下载码额度规则 |

首期产物：`ciban-english-<version>-windows-x64-setup.exe`、`ciban-french-<version>-windows-x64-setup.exe`。每个包包含同版本 Server、两种位数的 TSF DLL、设置程序、运行数据与许可；打包不包含私人打字数据、密钥或正式下载码。

## 首轮体验范围

先交付能在真实应用中日常打字的系统输入法：全拼中文输入、候选旁目标语言释义、空格/数字选词、候选翻页、组合文本编辑、中英文切换、必要标点、基本个性化学习、安装启用与卸载。

沿用上游原生候选窗和 WinUI 设置，围绕本产品收敛：

- 中文字号与选中状态优先；英法译词为次级，长释义不挤压候选命中区。
- 使用现有候选渲染布局适配深浅色、100%/150%/200% DPI 和屏幕边缘；先测布局再定样式。
- 学习详情在基本输入稳定后接入，提供鼠标入口与可配置快捷键。普通选词始终提交中文，查看详情不意外上屏、不抢宿主焦点。
- 首屏只解释“启用词伴 → 选择词伴 → 试打”，设置先保留外观、输入习惯、学习与隐私、关于/诊断，隐藏未交付功能。

第一次 Windows 交付不做桌面九宫格软键盘、语音、账号同步、AI 整句翻译、复习系统、自动升级或新的 UI 框架。既有数据仍未完成独立语言校审，不因为移植成功而把释义标成已校对。

## 开发与交付顺序

| 阶段 | 工作 | 可交付结果与门槛 |
| --- | --- | --- |
| 0：基线验证 | 统一工具链与依赖；只先构建现有 Server、x64/x86 TSF，验证词库布局、IPC 与普通应用输入；检查设置/打包依赖 | 编译报告、实际输入证据与阻塞清单。不要先大改 UI；上游联调脚本会注册 DLL/停服务，先审查，不直接对用户日常环境运行 |
| 1：英语可测试包 | 产品身份参数化并同时定义法语身份；共用词义模块与数据打包；英语安装器、精简启用指引 | 可安装英语测试包；记事本、浏览器与聊天应用真实选词/编辑通过；与微软拼音及上游青简互不覆盖 |
| 2：法语同轮接入 | 使用同一配置与构建流程装配法语；检查重音、长释义、读音保护、已知词性/性别展示 | 法语测试包，双包同机切换、数据隔离、升级一个/卸载一个后另一个可用 |
| 3：完整验收 | 学习详情、设置与候选外观；32 位宿主、DPI、多屏、宿主切换、崩溃恢复、升级回退；签名及受限宿主验证 | 可分发测试版本、兼容矩阵、性能报告、安装升级记录、配套源码与许可。未验证项明确写出 |

各阶段交付一个能检查的结果。英语先打通输入闭环，法语结构提前布局；两种语言的最终版本共用构建与回归流程。先完成阶段 0 才能根据真实阻塞给工期，不预先承诺几天正式发布。

## 质量标准

测试使用固定的自行编写输入内容，不记录用户私人聊天文本。

| 范围 | 必须验证的结果 |
| --- | --- |
| 输入正确性 | 全拼、连续输入、空格/数字选词、翻页、删除、Esc/Enter、标点、Ctrl+C/V/Z/A、移动光标、切输入框和中英切换无丢字、重复上屏或误提交 |
| 宿主兼容 | 记事本、Edge/Chrome 输入框、微信、Word 或 WPS；记录实际应用版本与位数，至少覆盖一个 32 位宿主；Windows 搜索等系统宿主另列结果 |
| 会话与恢复 | 切宿主/窗口不会把旧候选提交到新输入框；Server 退出、断管道与恢复时不挂起宿主、不静默吞键；组合文本回退行为须实际验收 |
| 英法共用行为 | 固定同字不同读音、词组、缺释义、法语重音与长内容，PC 和 Android 共用词义模块结果一致；法语不套英语等级资料 |
| 双包 | 独立启用、切换、学习文件、管道和卸载；单包升级不影响另一个；同版本与旧 DLL 升级兼容 |
| 视觉与交互 | 深浅色、DPI、多屏和屏幕边缘，无截断关键中文、遮挡、抖动或焦点抢占；鼠标和键盘都能完成常用任务 |
| 性能 | 固定机器 release 构建测真实按键到可见候选 p50/p95、冷启动、空闲/输入 CPU 与内存、连续输入。热态 p95 ≤50ms 是建议目标，阶段 0 建立基线后冻结预算；不以 JNI/引擎耗时代替端到端数字 |
| 安装发布 | 全新用户安装、系统输入源可见、登录恢复、覆盖升级和卸载；不强制修改用户默认键盘，不要求关闭 UAC/安全保护；失败可恢复 |

自动化分三层：共享词义/核心固定序列回归；Server↔TSF 协议与双产品隔离测试；在 Windows 实际宿主中操作验收。Windows CI 只证明能构建和代码测试通过，不能证明全部宿主输入体验。

## 提前处理的真实阻塞

1. **uiAccess / 候选窗可见性。** 上游默认将 uiAccess 写入 Server manifest，没有签名时上游要求 `QINGJIAN_UIACCESS=0`，并注明部分系统/UWP 候选可能被遮挡。开发包先关闭并声明该范围；正式体验需验证符合平台要求的签名、安装位置与候选呈现路径，不能靠让用户关闭 UAC 或自动导入根证书解决。UIAccess 的适用条件也要核实，不把它视为随意置顶的工具。
2. **安装与正在加载的 DLL。** 沿用上游按版本命名的 DLL 与延后删除方案；必须配套协议兼容、服务启动和数据不可变布局，不能把运行中的 DLL/词库直接覆盖。
3. **隐私与网络。** 默认无逐次输入日志、无详细内容日志，云预测关闭，首期不检查上游更新。输入学习记录为本地必要数据，用户可清理；诊断导出只含错误与版本等信息。
4. **工具链和设置运行时。** 检查 Rust 固定版、MSVC/Windows SDK、x86 target、Inno 与 WinUI 运行时；下载固定版本并记录校验，不能因设置依赖失败重写整个 UI。
5. **既有官网下载规则。** 当前每码领取一个 APK。PC EXE 接入官网需单独定义授权对象/版本与核销规则，不改已发行安卓码的含义或重置账本；此项不阻塞本机测试包交付。
